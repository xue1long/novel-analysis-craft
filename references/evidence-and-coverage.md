# 证据、覆盖与不确定性

## 来源说明

- 未提供可见原文或笔记时，仍可基于一般知识或可访问的公开简介继续分析；把未经原文核对的内容标为低置信度解读。
- 区分用户材料、公开简介和模型记忆。只有实际可见的来源才能登记为证据；不把记忆中的情节、原句或页码伪装成原文证据。
- 以转述为主。原句只保留最短必要片段，避免复现大量原文；引用必须逐字来自可见来源。
- 技巧迁移到全新情境，描述结构机制，不复制人物、独特意象、句式或作者的辨识性风格。
- 对用户上传材料的处理范围服从本次请求和适用产品规则；不得把原文另行发布或扩写成替代阅读版本。

## 证据登记

为可复查的来源片段创建稳定条目：

~~~json
{
  "evidence_id": "E001",
  "chapter_id": "ch03",
  "chunk_id": "c014",
  "locator": "第3章，批次 c014，第2段",
  "paraphrase": "主人公拒绝了看似能解决债务的匿名捐款。",
  "short_quote": ""
}
~~~

定位优先级：

1. 原文明确给出的页码、章节、小节、段落或行号；
2. 用户提供的稳定章节 ID 与批次 ID；
3. 若文本有清晰空行分段，可标注批次内段落序号；
4. 若没有更精确定位，只标章节/批次，不猜页码或原文位置。

给每个分析结论分配 claim ID；有可见来源时引用 evidence ID。无可见证据的结论可继续保留为低置信度 inference 或 evaluation，`evidence_refs` 留空并说明待核实之处。不要给它伪造 evidence ID。

## 覆盖登记

使用三个集合，不要混为一谈：

- expected_chapter_ids：用户明确声明此范围应包含的章节；
- received_chapter_ids：已收到至少一段可分析材料的章节；口头声明、空文件和占位文字不计；
- processed_chapter_ids：已完成至少一轮结构化梳理的章节。

计算覆盖率时使用 processed / expected。若用户没有声明完整章节清单，覆盖率为 unknown，不得假称 100%。待处理或未收到章节必须显示在 pending 清单中。

completeness 取值：

- complete：已声明的分析范围内，每个预期章节均收到且已处理；
- partial：已知范围中仍有缺章或未处理章节；
- unknown：没有可靠的预期章节清单，或无法判定范围。

即使覆盖率达到 100%，也只说明用户声明的范围已处理；若范围是选章，不得声称整本小说完整。

## 断点恢复

checkpoint 至少保留：

- work title、scope、depth、上次更新时间；
- 预期、已收、已处理、待处理章节 ID；
- 所有 source chunk 的 ID、章节 ID、内容 SHA-256 与可读取的来源位置，以及 evidence ID；哈希按 JSON 解码后的 `content` 字符串的 UTF-8 字节计算，checkpoint 不复制原文；
- 每阶段状态与质量门槛；
- claims、technique cards、SOP、未解决问题；
- last_processed_chapter_id 和 next_action；
- correction_log。

恢复时先确认作品名一致，再检查新旧 chunk ID、章节 ID 与内容哈希。相同 ID + 相同章节 + 相同哈希只算一次；相同 ID 对应不同章节或内容则标记冲突并询问或重新分配 ID，不能静默覆盖。原来源无法重新读取时，不声称已复核旧证据。先处理未处理批次；只有当新证据可能影响既有结论时，才回查对应旧结论，并在 correction log 记录修改。

## 不确定性处理

出现以下情况时继续分析可确认的部分，把相关判断标为待核实；不伪造引文和位置：

- 只有作品名，没有原文或用户笔记；
- 章节号、页码或引用内容在材料中不可见；
- 预期章节缺失，导致所谓高潮、结局或完整人物弧无法确认；
- 引用 ID 不存在或指向不同章节；
- 对主题、动机或因果的解释缺乏具体事件支撑。

明确说明信息来源、哪些判断未经核对，以及补充哪类材料可提高准确度；不要把补充材料设为继续分析的前提。
